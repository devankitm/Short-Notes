Git & GitHub Complete Notes

Easy Hinglish explanations, terminal commands, examples, collaboration workflow, common errors, interview questions and practice tasks.

1. Git aur GitHub kya hain?

Git ek version control system hai jo project ki history, file changes aur commits track karta hai. GitHub ek online platform hai jahan Git repositories host aur teams collaborate kar sakti hain.

Yaad rakhein: Git aapke computer par bhi kaam karta hai. GitHub online hosting, Pull Requests, Issues aur code review deta hai.
  • Git = version history tool
  • GitHub = hosting and collaboration platform
  • Git use karne ke liye GitHub account compulsory nahi hai.

2. Install and verify Git

Windows par Git install karke Git Bash ya terminal open karein. Installation verify karne ke liye:

Bash / Git
git --version

Version print hota hai to Git command available hai. Command not found aaye to installation/PATH check karein.

3. First-time configuration

Git commits me author name aur email store karta hai. Apni details set karein:

Bash / Git
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global --list

--global sabhi repositories ke liye hai. Ek repo ke liye us folder me --local use karein.

4. Git workflow

Working Directory → Staging Area → Local Repository → Remote Repository
  • Working directory: jahan files edit karte hain.
  • Staging area: next commit ke liye selected changes.
  • Local repository: computer par saved commit history.
  • Remote: GitHub jaise server par repository.

5. Initialize a repository

Naye project folder me Git start karne ke liye:

Bash / Git
mkdir my-project
cd my-project
git init
git status

git init repository initialize karta hai aur git status current changes ka status batata hai.

6. Clone a GitHub repository

Existing GitHub project ko computer par copy karne ke liye repository page se URL copy karein:

Bash / Git
git clone https://github.com/USERNAME/REPOSITORY.git
cd REPOSITORY

USERNAME aur REPOSITORY ko actual values se replace karein.

7. Add and commit

git add changes stage karta hai; git commit staged snapshot history me save karta hai.

Bash / Git
git status
git add index.html
git diff --staged
git commit -m "Add homepage"
Tip: Commit se pehle git status aur git diff --staged check karein.

8. History and differences

Bash / Git
git log
git log --oneline --graph --all
git show
git diff
git diff --staged
  • git log: commit history.
  • git show: ek commit ka detail.
  • git diff: unstaged changes.
  • git diff --staged: staged changes.

9. .gitignore

.gitignore me patterns likh kar un files ko untracked rehne de sakte hain jinhe Git normally track na kare.

Bash / Git
# Dependencies
node_modules/

# Build output
dist/

# Local secrets
.env

# Logs
*.log

Important: .gitignore pehle se tracked file ko automatically untrack nahi karta. API keys/passwords commit na karein; leaked secret ko revoke/rotate karein.

10. Branches

Branch ek separate line of work hai, jaise feature ya bug fix par main branch ko disturb kiye bina kaam karna.

Bash / Git
git branch
git switch -c feature/navbar
git switch main
# Older alternative:
git checkout -b feature/navbar

Modern Git me branch switch/create ke liye git switch readable option hai.

11. Merge and conflicts

Feature branch ko target branch me merge karne ka example:

Bash / Git
git switch main
git pull
git merge feature/navbar

Merge conflict tab aata hai jab Git overlapping edits ko automatically combine nahi kar pata. Conflicted file edit karein, conflict markers remove karein, test karein aur phir:

Bash / Git
git status
git add path/to/file
git commit

12. Remote, origin and upstream

Remote ek named URL hai. origin clone karte waqt usually default remote name hota hai.

Bash / Git
git remote -v
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git remote set-url origin https://github.com/USERNAME/NEW-REPOSITORY.git

upstream aksar fork ki original repository ke liye remote name hota hai; ye naming convention hai, special keyword nahi.

13. Fetch, pull and push

Bash / Git
git fetch origin
git pull origin main
git push -u origin main
git push
  • fetch remote updates download karta hai, par current branch ko automatically integrate nahi karta.
  • pull fetch karke configured strategy se integrate karta hai.
  • push commits remote par upload karta hai.
  • -u upstream tracking set karta hai.

14. Push a local project to GitHub

  1. GitHub par New repository banayein.
  2. Local project folder me terminal open karein.
  3. Files commit karein, phir remote add karke push karein.
Bash / Git
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main

Agar remote repository me pehle se README/commits hain, histories different ho sakti hain. Push se pehle remote changes safely integrate karein; bina samjhe force push na karein.

15. Pull Requests and collaboration

Pull Request (PR) proposed changes ko discuss, review aur merge karne ka GitHub workflow hai.

  1. Feature branch banayein.
  2. Changes aur tests complete karein.
  3. Commit aur branch push karein.
  4. GitHub par PR open karein.
  5. Review feedback address karein.
  6. Checks pass hone ke baad authorized maintainer merge kare.
Bash / Git
git switch -c feature/search
# edit files
git add .
git commit -m "Add search feature"
git push -u origin feature/search

16. Fork vs clone

Fork GitHub par kisi repository ki aapke account me server-side copy hoti hai. Clone repository ko local computer par download karta hai.

Bash / Git
git clone https://github.com/YOUR-USERNAME/PROJECT.git
cd PROJECT
git remote add upstream https://github.com/ORIGINAL-OWNER/PROJECT.git
git remote -v

Open-source contribution me common flow: fork → clone → branch → commit → push → Pull Request.

17. Undo changes safely

Undo commands ko samajh kar use karein, kyunki kuch commands local work discard kar sakti hain.

Unstaged edits discard:

Bash / Git
git restore filename.html

Staging se remove, changes preserve:

Bash / Git
git restore --staged filename.html

Commit ko new reversing commit se undo:

Bash / Git
git revert COMMIT_HASH

Recent local commit undo, changes staged rakhein:

Bash / Git
git reset --soft HEAD~1
Caution: git reset --hard uncommitted changes delete kar sakta hai. Shared history rewrite karne se pehle team se coordinate karein.

18. Stash and rebase

Stash uncommitted changes ko temporarily side par rakhta hai:

Bash / Git
git stash
git stash list
git stash pop
git stash apply

Rebase commits ko kisi naye base ke upar replay karta hai; history linear ho sakti hai, lekin commit hashes change ho sakte hain.

Bash / Git
git fetch origin
git switch feature/search
git rebase origin/main
# After resolving conflicts:
git rebase --continue
# Cancel rebase:
git rebase --abort

Public/shared commits ko rebase karne me caution rakhein.

19. HTTPS, SSH and security

GitHub remote authentication HTTPS ya SSH se ho sakti hai. HTTPS credential manager/browser sign-in use kar sakta hai; SSH me public key GitHub account me add karte hain.

Bash / Git
git remote -v
# HTTPS example
git remote set-url origin https://github.com/USERNAME/REPOSITORY.git
# SSH example
git remote set-url origin git@github.com:USERNAME/REPOSITORY.git
Security: Password, access token aur private SSH key kisi se share na karein. Inhe code/repository me commit na karein.

20. GitHub features

  • README.md: project intro, setup aur usage instructions.
  • Issues: bugs, tasks aur ideas track karna.
  • Pull Requests: changes review and merge karna.
  • Actions: CI/CD workflows automate karna.
  • Releases: versioned software releases publish karna.
  • Projects: work planning and tracking.
  • Pages: static HTML/CSS/JS website hosting.

21. GitHub Pages

GitHub Pages static websites (HTML, CSS, JavaScript) host kar sakta hai. Portfolio ya Code-Notes site ke liye useful hai.

  1. Website files repository me push karein.
  2. Repository Settings → Pages open karein.
  3. Publishing branch/folder select karein, jaise main aur /(root) (project structure ke hisaab se).
  4. Save karke deployment URL check karein.
GitHub Pages static hosting hai; server-side Node.js process ya database server directly run nahi hota.

22. Common errors and fixes

Not a git repository

Correct folder me jaayein ya repository initialize karein.

Bash / Git
cd path/to/project
git status

Nothing to commit

Changes nahi hain ya stage nahi hue. Status check karein.

Bash / Git
git status
git add filename
git commit -m "Describe change"

Non-fast-forward / rejected push

Remote par new commits ho sakte hain. Pehle fetch/pull karein; uncommitted changes hon to rebase se pehle commit ya stash karein.

Bash / Git
git fetch origin
git pull --rebase origin main

Conflict aaye to resolve karke rebase continue karein.

23. Best practices

  • Small, focused commits banayein.
  • Clear messages likhein, jaise Add SQL notes page.
  • Commit se pehle status aur diff review karein.
  • Feature ke liye separate branch use karein.
  • Secrets ko repository me kabhi commit na karein.
  • Destructive commands samjhe bina run na karein.
  • README me installation, usage aur contribution steps likhein.

Bash / Git

# Branches

# Remote collaboration
git remote -v

git pull
git push

# Undo / stash
git restore filename
git restore --staged filename
git revert COMMIT_HASH
git stash
git stash pop
